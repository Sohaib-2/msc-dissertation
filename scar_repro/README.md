# SCAR reproduction

`../scar_baseline/` is an unmodified clone of the upstream SCAR implementation (Chen et al.,
NeurIPS 2025, `github.com/WhitolfChen/SCAR`). It is never edited. Everything in this folder is
the work built around it: the runnable configurations, the runners for Colab and RunPod, and the
documented differences from the paper's settings. Keeping the two apart lets the dissertation say
exactly what came from upstream and what was changed.

## What SCAR does

SCAR is a distillation-conditional backdoor. The attacker ships a teacher that looks clean, and
that classifies trigger images correctly, but any student distilled from it comes out
backdoored. The backdoor lives in the weights and in the distillation dynamics rather than in
anything visible in the teacher's outputs. Three stages:

1. `pretrain.py` learns a universal additive trigger.
2. `SCAR.py` runs the bilevel optimisation that bakes the dormant backdoor into the teacher.
3. `test_distillation.py` distils a student and measures clean accuracy and attack success.

Three numbers decide whether it worked: the teacher's accuracy should stay high, the teacher's
attack success rate should stay low (that is the stealth), and the student's attack success rate
should be high after distillation.

## Why this is here

SCAR is the baseline the dissertation's own attack is compared against, and reproducing it
serves two purposes. It confirms that the harness behaves as published before anything is built
on top of it, and it establishes the weight-space attack that the runtime attack is contrasted
with. The point of departure is that SCAR needs the teacher's weights; the attack in
`../runtime_attack/` needs only its serving path.

## Changes from upstream

1. `requirements.txt` here, rather than the upstream `environment.yaml`.
2. `patch_epochs.py` exposes the hardcoded epoch and step counts as environment variables, with
   the paper values as defaults. This allows a short proof configuration and the full one from
   the same code. With no variables set the behaviour is the upstream behaviour.
3. The checkpoint-save gate was changed so that a teacher is persisted before epoch 200. This is
   documented with the run it affected, in `results/faithful_run_2026-06-15/RESULTS.md`.

## Results

| Run | Teacher ACC | Teacher ASR | Student ASR |
|---|---|---|---|
| Short configuration, 2026-06-04 | 70.7% | 4.8% | 63.7% |
| Cost-bounded reproduction, 2026-06-15 | 80.6% | 1.83% | 80.2% final, 91.5% peak |
| SCAR paper | ~86% | <2% | ~90% |

The second run reproduces the mechanism at close to paper strength. It is a cost-bounded partial
reproduction rather than a full one: the attack stage was stopped at 30 epochs instead of 200,
because the measured cadence of about 13 minutes per attack epoch put the full run at roughly 43
GPU-hours. The teacher's clean accuracy is the one number still short of the paper's, which is
consistent with stopping early, since it was still climbing. Both deviations are recorded in
`results/faithful_run_2026-06-15/RESULTS.md` and in the dissertation.

## Running it

```bash
bash run_short.sh <path-to-scar-clone>      # reduced epochs, a few hours on a T4
bash run_faithful.sh <path-to-scar-clone>   # paper settings
```

`Colab_SCAR_short.ipynb` is the same short configuration for a free Colab T4, generated by
`build_notebook.py`. `smoke_test.py` checks that the epoch patch applies cleanly on a CPU before
any GPU time is paid for.
